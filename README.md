# FluidHUD

FluidHUD — небольшой media HUD для Windows 10 и 11. Он показывает текущий трек поверх остальных окон, не забирает фокус и исчезает сам, когда больше не нужен.

Я начал этот проект из-за обычной бытовой проблемы: стандартная панель Windows слишком большая, появляется не всегда вовремя и почти не настраивается. Хотелось оставить только обложку, название, прогресс и несколько действительно полезных действий.

Автор — **CatYaderka**.

## Что уже работает

- текущий трек из любой программы, которая публикует GSMTC session;
- название, исполнитель, альбом и обложка;
- центральный квадратный crop для неквадратных обложек;
- Play/Pause поверх обложки при наведении;
- Previous и Next по сторонам progress bar;
- перемотка кликом и перетаскиванием ползунка;
- бесконечная прокрутка длинного названия без пустого участка;
- глобальная настраиваемая горячая клавиша;
- прозрачность HUD от 20 до 100%;
- настройка времени показа и скорости анимации;
- отображение общей громкости и mute;
- запуск вместе с Windows;
- позиция сверху или снизу активного экрана;
- корректная работа на нескольких мониторах с разным DPI;
- один экземпляр приложения и один HWND оверлея;
- Release-сборка в одном EXE.

## Поведение при смене трека

Некоторые проигрыватели сначала очищают media session, а уже потом публикуют новый трек. FluidHUD не показывает в этот момент «Нет активного трека», а держит прошлые данные минимум пять секунд.

Обложка обрабатывается отдельно. Если проигрыватель отдаёт её позже текста, старое изображение остаётся на месте до загрузки нового. Если обложки действительно нет, она очищается после завершения повторных запросов.

Когда HUD уже открыт, смена трека или громкости не запускает анимацию заново. Обновляются данные и сбрасывается таймер скрытия. Если Fade Out уже начался, он отменяется на том же окне.

## Почему здесь нет системного Acrylic

Acrylic и Mica живут в DWM отдельно от XAML. Для обычного окна это нормально, но у короткоживущего оверлея системная поверхность иногда успевает показаться раньше интерфейса. Получается прозрачный прямоугольник, рамка или короткая вспышка blur.

В FluidHUD используется прозрачный composition backdrop и собственная XAML-карточка. Перед первым кадром окно ненадолго cloaked, системная non-client рамка отключена, а затем HUD показывается уже с запущенной анимацией. Эффект менее «мыльный», зато ведёт себя одинаково на разных сборках Windows.

## Требования

Для запуска:

- Windows 10 2004 или новее;
- x64, x86 или ARM64.

Для сборки:

- Windows;
- .NET 8 SDK;
- Windows 10/11 SDK;
- PowerShell 5.1 или PowerShell 7;
- доступ к NuGet.org при первом restore.

## Сборка

Из обычной командной строки `cmd.exe`:

```bat
build.cmd
```

Из PowerShell:

```powershell
Set-ExecutionPolicy -Scope Process Bypass -Force
.\build.ps1
```

Готовый файл:

```text
release\FluidHUD.exe
```

Другие архитектуры:

```bat
build.cmd -Platform x86
build.cmd -Platform ARM64
```

или из PowerShell:

```powershell
.\build.ps1 -Platform x86
.\build.ps1 -Platform ARM64
```

Скрипт всегда публикует Release, включает .NET runtime, Windows App SDK, native-зависимости и ресурсы в single-file bundle, а затем проверяет, что рядом с EXE не осталось обязательных файлов.

В проекте включён `EnableMsixTooling`, потому что Windows App SDK использует этот target для встраивания `resources.pri` в single-file. Само приложение остаётся обычным unpackaged EXE.

## Автоматическая сборка в GitHub Actions

Workflow `.github/workflows/build.yml` запускается при push в `main`/`master`, pull request и вручную через вкладку Actions.

Матрица на `windows-2022` и .NET SDK 8.0.408 собирает x64 и ARM64. Внутри каждого artifact исполняемый файл сохраняет исходное имя:

```text
FluidHUD.exe
FluidHUD.exe.sha256
```

Имя не меняется после publish, потому что WinUI resource identity и встроенный PRI создаются вместе с финальным EXE. Артефакты обычных сборок хранятся 14 дней.

Тег `v*` создаёт GitHub Release. Чтобы архитектурные файлы не конфликтовали по имени, Release содержит архивы, но внутри каждого остаётся неизменённый `FluidHUD.exe`:

```text
FluidHUD-win-x64.zip
FluidHUD-win-arm64.zip
```

Новый релиз:

```powershell
git tag v1.0.2
git push origin v1.0.2
```

В самом репозитории и workspace ZIP-файлы не создаются.

## Первый запуск

1. Запустите `FluidHUD.exe`.
2. Нажмите на поле горячей клавиши.
3. Введите удобное сочетание, например `Ctrl + ~`.
4. Настройте прозрачность, время показа, скорость и положение.
5. При желании включите запуск вместе с Windows.
6. Нажмите «Начать».

Настройки находятся в:

```text
%LocalAppData%\FluidHUD\settings.json
```

Автозапуск регистрируется только для текущего пользователя:

```text
HKCU\Software\Microsoft\Windows\CurrentVersion\Run
```

Права администратора не требуются.

## Управление

- горячая клавиша показывает или скрывает HUD;
- Play/Pause появляется при наведении на обложку;
- клик по полосе прогресса перематывает трек;
- ползунок можно тянуть даже за пределами полосы;
- Previous и Next переключают треки;
- шестерёнка открывает настройки;
- кнопка питания полностью завершает процесс.

## Как устроен проект

```text
FluidHUD/
├─ src/FluidHUD/
│  ├─ Controls/       MarqueeText и SeekBar
│  ├─ Converters/     XAML-конвертеры
│  ├─ Interop/        Win32 и DWM
│  ├─ Models/         настройки и media snapshot
│  ├─ Services/       GSMTC, artwork, volume, startup, cache
│  ├─ ViewModels/     состояние HUD и timeline
│  ├─ Views/          overlay и настройки
│  └─ Assets/         иконка и noise texture
├─ build.ps1
├─ FluidHUD.sln
└─ README.md
```

Несколько важных деталей реализации:

- media events сериализуются через `SemaphoreSlim`;
- устаревшие async refresh отменяются;
- обложки хранятся в byte-bounded LRU-кэше;
- неквадратные изображения обрезаются по центру до помещения в кэш;
- progress вычисляется между системными timeline events;
- seek отправляется в GSMTC в ticks;
- настройки записываются через временный файл и атомарную замену;
- второй экземпляр FluidHUD сразу завершается;
- HUD выбирает монитор активного приложения, а не всегда основной экран.

## Ограничения

FluidHUD видит только проигрыватели, которые интегрированы с системными media controls Windows. Если старый плеер не публикует GSMTC session, получить трек из него без специальных интеграций нельзя.

Live streams и некоторые браузерные источники могут запрещать перемотку. В этом случае команда seek будет отклонена самим источником.

Обычный topmost HUD работает поверх оконных и borderless-fullscreen приложений. Exclusive fullscreen, UAC, secure desktop и защищённое видео могут находиться выше любого desktop-окна.

Если запуск завершился ошибкой, FluidHUD показывает системное окно с причиной и путём к журналу:

```text
%LocalAppData%\FluidHUD\FluidHUD.log
```

## Перед повторной сборкой

Если обновлялись зависимости или Windows App SDK, лучше удалить старые артефакты:

```powershell
Remove-Item .\src\FluidHUD\bin, .\src\FluidHUD\obj, .\release `
    -Recurse -Force -ErrorAction SilentlyContinue
```
